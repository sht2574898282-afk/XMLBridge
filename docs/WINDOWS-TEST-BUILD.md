# Windows 便携测试版

2026-10-22。用户选择：接近当前 Mac 新版式的 Windows 界面。首个目标为 Windows 10/11 x64；交付本地 ZIP，不自动上传 GitHub。

## 界面与范围

沿用已确定的 Mac 交互：首次开始页、源文件到目标版本的中央转换区、批量文件侧栏、项目选择和影响弹窗、允许有损转换，以及独立的结果窗口。Qt 使用 Windows 控件与字体，保留既有 Logo。复用原转换核心，不改变 Mac 启动入口或 SwiftUI 界面。

## 实现顺序与完成条件

1. `xmlbridge/media_paths.py`：处理本地 file URI、Windows 盘符和相对路径。针对路径解析、跨格式媒体引用及已有 Mac 行为进行回归。
2. `xmlbridge/windows_gui.py`：用 PySide6 实现上述界面，直接调用既有核心，在后台线程分析/导出，支持取消、批量部分失败及源文件改变校验。增加 UI 流程测试。
3. `xmlbridge/windows_launcher.py`、`scripts/windows/launcher.c`：无控制台启动、文件参数、自检和本地错误日志。使用同包运行时，不要求用户配置 Python。
4. `scripts/build_windows_portable.py`：构建 Windows x64 PE 启动器，收集独立 Windows CPython 3.12.13、锁定的 Windows Qt/lxml 组件和许可；应用自身只交付字节码；源路径统一为中性相对路径。生成 ZIP、文件清单、SHA-256、自检入口和中文试用说明。
5. 验证：现有全套回归、新 UI 和路径测试；检查 Windows EXE/DLL 架构与依赖；检查 ZIP 内部压缩内容、个人路径和元数据；解压后核对内容与文件清单。明确区分 Mac 上的 Qt 流程检查、Windows 静态包检查及用户待做的 Windows 真机运行。

本机目前没有可用 Windows 运行环境。可生成 Windows 便携运行包，但不得把 Mac 上的 Qt 测试标记为 Windows 真机验收。原 macOS 发布和源代码保密边界保持不变；不提交、不推送、不公开 Windows 测试包。
