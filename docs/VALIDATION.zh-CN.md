## 剪辑软件实测

测试使用独立校验工程和生成的 640×360、25 fps、8 秒素材。基础时间线从 01:00:00:00 开始，共 5 秒：第一段取源 0–2 秒，中间空隙 1 秒，第二段取源 3–5 秒，第一段有普通标记。

| 软件与方向 | 实际结果 |
| --- | --- |
| Resolve 21.1.1，FCPXML 1.8 升至 1.8–1.14、1.14 降至 1.8 | 实际导入，项目范围 90000–90125 帧；片段为 90000–90050、90075–90125 帧，源范围保持 0–2、3–5 秒 |
| Resolve 21.1.1，FCPXML→XMEML 4/5 | 实际导入并核对相同时间范围；立体声音频写为两个关联单声道 |
| Resolve 21.1.1，XMEML→FCPXML 1.9 / 1.14 | 实际导入并核对相同时间范围；修正了导入所需的 library 外壳 |
| Resolve 21.1.1，产品输出的静态旋转与音量 | 第一段旋转读回 30°；两个音频声道均读回约 −6 dB，误差约 10⁻¹⁵ dB；第二段保持 0° / 0 dB；剪辑点及源范围一致 |
| Final Cut Pro 11.2，1.8→1.9 | 实际导入并打开时间线，2 秒片段 + 1 秒空隙 + 2 秒片段，普通标记可见，画面可显示 |
| Final Cut Pro 11.2，产品 XMEML→FCPXML 1.9 | 明确选择 Rec.709 后实际导入并打开新项目；无格式警告，01:00:00:00 起点、2 + 1 + 2 秒及标记保持 |
| Final Cut Pro 12.4 Creator Studio | 启动后停在订阅激活页；未开通订阅，未验证导入 |
| Premiere Pro | 本机未安装，未验证导入 |

变速实验观察到不同格式的端点和音高校正规则差异，现有样例不足以建立通用可靠映射；因此跨格式变速、倒放和冻结帧继续阻断。同格式保留已有表达，但不声称已完成所有复杂效果的画面、声音比对。

## 独立应用检查

- Apple Silicon `.app` 已完成打包自检、格式定义读取检查和本地签名检查。
- 通过桌面界面实际添加双项目文件、分析并导出 FCPXML 1.9；生成新文件和 HTML / JSON 报告，两个项目均保留，界面显示结构与时间线通过、软件导入未验证。
- 不需要系统 Python。打包保留原始许可和来源资料；移除未使用的 Qt PDF、虚拟键盘及 Qml / Quick 模块。

本记录只对应上述样例和软件版本。用户的每份转换报告仍独立显示本次检查状态，历史样例通过不会自动把“软件导入”设为通过。详细支持范围见 `CAPABILITIES.zh-CN.md`。
